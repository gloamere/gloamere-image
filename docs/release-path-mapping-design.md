# 发布构建源码路径映射设计（构建前）

对已构建 EXE 的实际字节检查发现，本机用户目录出现于编译器保留的依赖源码定位信息。发布版需要可诊断的源码位置，但无需携带构建机器的用户目录。使用官方 rustc --remap-path-prefix，在独立发布脚本中动态映射工程、依赖源码和构建输出前缀，保留静态 CRT、既有优化、feature 和 /Brepro；不写入硬编码的本机路径，不修改系统或其他项目配置。

脚本只设置本次进程的编码 Rust flags，退出恢复原值；锁定 Cargo.lock，构建 workspace/release/全部测试与样例目标，再可选运行同一配置的 release 测试。映射导致 Cargo 按参数构建新产物，这是发布路径处理，不进行重复干净构建或新增可重复性实验。

验收以主程序及配对 worker 的实际 UTF-8/UTF-16 字节扫描、59项 release 回归、静态CRT/未签名检查、D3D12窗口及导出故障回归为准。映射不能替代扫描，也不承诺处理所有平台链接器的独立路径字段。若本轮构建失败，保留已验证检查点并准确报告；不能按新路径隐私验收交付未验证二进制。

参考：[rustc 源码路径映射](https://doc.rust-lang.org/rustc/remap-source-paths.html)。
