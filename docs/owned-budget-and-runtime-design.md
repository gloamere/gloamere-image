# 预算所有权与 portable 运行时设计（实现前）

只读复核确认临时准入令牌返回后过早释放：快照还在哈希/IPC 或图像结果还在
等待 UI 消费。第二版预算必须跟随数据所有权，不仅跟随函数调用栈。

正确性夹具串行执行，避免多个测试进程内的虚拟 UI/保守解码暂存同时争用全局预算，
将预期的资源拒绝误报为像素功能失败。预算并发测试显式启动八线程，单独验证并发
准入与丢弃。快照首次预留按文件实际长度，文件增长时在扩容前增加预留。

引入 Snapshot（bytes + reservation）和 Pixels（RgbaImage + reservation），
只允许受控构造，Reservation 可 split，将操作峰值的一部分转为持久缓冲令牌。
Snapshot 的 Vec 容量计入预算，移动到 IPC 输入线程后也保持令牌，最后引用释放
才归还；Pixels 可放入 Arc，加载结果、编辑结果、当前图和撤销均持有相同令牌，
共享引用不重复计数。取消/旧世代丢弃/发送通道断开均靠 RAII 回收。
纹理另计 egui CPU/GPU 估算与一次上传暂存；驱动提交和缓存实际生命周期无法
用这些逻辑令牌精确约束，仍不能称严格进程内存上限。操作预留与持久缓冲分别
计数，避免新的持久令牌被临时预留再次计入。测试独立 Budget 实例，验证
并发通道排队、取消/丢弃、Arc 最后引用释放及 split 的会计守恒。

Portable 依赖检查发现 VCRUNTIME140.dll，当前开发电脑有它不能证明干净 Windows
可运行。采用 Windows x64 target 专用 +crt-static 构建，保持 Rust/UI 共享代码；
构建后重新 dumpbin 检查两 EXE，不复制系统 DLL，不修改安全设置。Mac 构建不
继承 Windows target 配置。静态 CRT 不是跨机器 GPU 驱动/系统 API 兼容性证明。

窗口 smoke 超时是失败证据。增加本任务日志和各阶段诊断，失败也保存进程采样；
先确认不带空闲采样的闭环，再定位 SDK、截图或重绘定时，不宣称物理 UI 输入已测。
