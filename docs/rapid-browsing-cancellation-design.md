# 快速翻图取消验证设计（测试前）

真实使用中，用户可能连按翻图键，上一张还在解码便已经选择下一张。串行打开 1000 次的窗口运行验证了长期使用，但没有直接覆盖请求重叠和取消传播。本次增加针对现有单工作线程、单待处理请求和 generation 过滤的回归，不新增产品入口。

使用实际 App 和 Windows 文件/解码工作线程，连续发送 1000 个交替图片请求，逐个保留上一请求的取消令牌，最终选择带独特尺寸和像素的图片。验收前 999 个令牌被取消、最终 generation/文件/像素相符、旧响应不能覆盖最后选择、原文件未变。随后选择无效文件，应得到可读错误，再选择正确文件可恢复；最后释放 App 并有界等待已拥有内存回到测试前水平。该测试检验内部加载行为，不能宣称真实键盘连按已经验收，也不代表库函数支持解码中途抢占。

普通切图不再立即在画面中央显示解码提示。每代请求分别记录开始时间，仅在加载持续至少 200 ms 后显示原有底部状态条；保留旧画面时，状态文字前置“画面仍是上一张”，避免长文件名截断身份提示。加载结束、失败、取消或切换为剪贴板图片时清除计时。失败仍立即显示错误与画布角落的旧画面标记，不受加载延迟影响。

同目录切图取消正在运行的缩略图任务，只淘汰本次打开文件的缩略图，保留其他文件已有的有界缓存；显式重新打开同名文件时，当前缩略图会重新生成，跨目录或手动刷新继续使全部缓存失效。其他未重新打开的文件被外部修改后，缩略图通过手动刷新更新，本次不增加文件监控。回归使用可控的 `Instant` 检查 199/200 ms 阈值与最新请求计时，检查渲染文本只有一处底部加载反馈、失败提示立即可见，以及同目录其他缓存保留、外部改图重新打开时仅当前缓存失效、旧缩略图响应隔离、跨目录与手工刷新失效。没有增加邻图缓存或并行解码，解码库内部的不可抢占调用仍可能延迟最后一次选择；Debug 与 Release 的实际切图延迟需要分别测量。

## 2026-10-19 第二轮：新图就绪后替换当前画面

用户体验确认首轮仍存在短暂空白/Logo：`open_now` 对超过 400 万像素的当前图提前清空像素和纹理。现在加载期间保留当前图、缩放和平移；新图在后台完成解码、透明度结果复用和 CPU 显示分块准备后，由界面提交纹理，再更新文档身份与视图。失败或取消继续保留原图；显示预算不足也不把旧画面标成新文件。初次没有图片时仍使用正常空态。

`Pixels` 缓存有独立预算的 `PreparedDisplay`，后台按行转换预乘色彩；主线程共享 `Arc<ColorImage>`，撤销重复利用既有准备结果。编辑、剪贴板像素与动画帧在原后台任务中准备，编辑历史淘汰预检同时覆盖输出显示数据及 GPU 交接峰值。上传同网格采用 `set_partial([0, 0], …)`，锁定版本的 renderer 因此复用 GPU 纹理；不同网格先建立全部新分块再替换。CPU 和 GPU 交接都保留拥有者与预算至后续帧。

最近原图缓存最多 2 项、192 MiB，原始 RGBA 与显示像素合计计费，复用 Arc 所有权，不重复分配。静态图才缓存；编辑、导出或预算压力主动清理。缓存身份与实际快照读取共用同一 `File` 句柄，核对长度、修改时间、原生文件 ID/变更时间以及当前路径，拒绝同名替换、外部改写和 A→B→A 路径交换误绑定。元数据无法可靠获取时放弃缓存。没有添加后台邻图预读或并行解码队列。

缩略图独立读取首帧，不计算来源哈希、不构造动画播放源，方向/透明度与缩略图 ICC 处理保留。JPEG 增加无 Rayon 的固定 `jpeg-decoder 0.3.2`，使用 IDCT 缩小；不支持该预览类型时回退现有解码器。PNG/GIF/WebP 不具备通用原生缩小解码，仍需解码压缩像素，避免宣称所有格式都只解码 96 像素。读取按 64 KiB 检查取消，PNG 行/Adam7 行、透明度与哈希阶段增加取消边界；JPEG/WebP 内部的单次 CPU 调用及 OS 调用仍不能强制抢占，旧请求不会覆盖最新 generation。

AI 检测入口迁至“更多（…）→ AI 检测当前图片”，默认不开启，展开菜单不触发检测。

扩大库回归时，更新器的 46 项 Windows 私有路径/安装恢复检查失败。使用前轮 17:45 的 242-test 产物和本轮 259-test 产物，分别运行全部 `updater::`，均为 64 通过、46 失败，失败名称集合逐项一致；`src/updater` 无修改。两项单独对比的代表错误为 `PathOwnerMismatch` 和 `PathUnsafeWriteAccess`，当前临时目录为 `D:\Temp`。本轮未修改系统 ACL 或放宽安全检查。基线和当前日志分别为 `test-output/navigation-20261019/baseline-updater-20261019.log`、`current-updater.log`，不能将全库回归表述为全部通过。

第二轮相关回归：非 updater 库测试 149 通过；UI 102 通过、3 忽略；核心集成 19 通过；动画集成 19 通过、1 忽略，共 289 通过、4 忽略。新增覆盖大图等待/失败时保留画布、预算失败不提交新身份、真实 partial texture delta、编辑历史显示峰值预检、缓存身份/淘汰/取消，以及预览方向/ICC/透明度/16 位/Adam7/首帧/取消边界。小图预览只缩小、不放大。

实际窗口复测还发现原有调度遗漏：缩略图在 `ui()` 后段启动，而 `logic()` 已完成本帧的忙碌检查；worker 不主动锁 egui 请求重绘，空闲窗口可能不再轮询该结果。启动缩略图时补充一次 16 ms 后的重绘，随后沿用正常忙碌轮询。修复前“列表＋更多”原生 smoke 60 秒超时；修复后同场景约 4 秒完成并收到两张缩略图，AI 检测菜单可见。
