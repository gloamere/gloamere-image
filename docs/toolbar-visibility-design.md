# 默认中文字体下的工具栏可见性修复设计

真实场景是用户打开 Windows 素材、在最小窗口翻图和切换 100% 显示。当前实际 D3D12 读回在默认微软雅黑下重复出现短按钮消失，而 SimHei 受控回退布局正常。图像、中文按钮与底部数值仍可见；不能仅凭内部编辑测试把工具栏判定为通过。

先核对 egui 已锁定版本的布局与绘制行为，以及默认/回退字体的按钮区域。修复优先使用现成 egui 布局和一致的交互高度；必要时将工具栏组织为稳定的两行，使翻图、缩放、编辑和导出都位于可见区域。保留共享 UI、现有快捷键和处理接口，不替换字体库或增加自定义 GPU 绘制。

验收必须包括默认微软雅黑和 SimHei 的实际最小 D3D12 窗口，检查短按钮、中文主操作和裁剪确认均可见；正常尺寸也需检查。用内部 UI 节点/绘制范围检查支撑布局判断，但不声称系统鼠标键盘已经验收。代码变化后重新执行质量门、同配置发布构建和真实导出闭环。最终 EXE 和旧长时间复验分别记录，不能混用版本证据。

第一轮统一 40 逻辑像素交互高度后，默认字体的短按钮恢复可见，但回退字体仍能复现遗漏。
因此不能把高度常量视为修复完成。下一步让换行工具栏使用显式顶对齐，避免字体高度差异参与行内居中；
裁剪固定区预留 140 逻辑像素，容纳统一高度按钮、选区尺寸和提示。两种字体均需再次实际查看。
