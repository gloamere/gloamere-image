# Windows 同目录浏览路径加固设计（实现前）

场景：用户在素材目录通过命令行打开单个文件名，或以不同大小写输入图片名，再使用上一张/下一张浏览。当前目录必须被当成有效父目录，当前素材在列表中只出现一次，保留用户输入的路径身份给加载/导出与来源核验。当前实现对空父路径read_dir失败，会退化为只看这一张；路径表示差异还可能重复加入同一文件。

修复：空父路径按当前目录枚举；同一目录精确文件名先替换为请求路径。Windows大小写候选只在名称折叠匹配时进行文件canonical身份比较，确认后替换而非重复加入，避免对整个目录逐个canonicalize。原图仍只读，不改文件名、不改工作目录、不扫描无关项目。

同目录队列继续至多10000条，并增加4MiB路径字符串累计边界，避免极长父路径目录挤占UI内存；这是逻辑UI预留内的有界列表而非新的硬进程沙箱。枚举循环与潜在文件系统调用前后检查现有取消令牌。单个无法中断的系统调用不能宣称即时取消，旧generation不替换新图。

验收使用实际Windows子测试进程：在独立临时素材目录以Unicode单文件名和大小写变化读取，验证三个同目录素材、当前图唯一、顺序可浏览及原图字节不变。子进程设置自己的cwd，不改变父测试进程cwd，不引入测试之间的全局竞争。取消枚举也须返回取消而非半成功。继续运行现有图像、导出、来源、worker和界面回归。


另在独立临时目录构造实际Windows长父路径及2500个空素材条目，验证4MiB累计路径边界、当前素材始终唯一且不会修改源PNG。仅使用标准文件API，不修改系统长路径策略；若该系统拒绝路径，须报告失败而非跳过。返回列表前再次检查取消，以覆盖排序期间的取消窗口。
