# 后续阶段设计：从同机测试版到可推广 Windows 版本

## 真实场景与顺序

首要用户是频繁查看本地素材、核对透明度与尺寸并导出正确副本的开发者和内容制作者。下一阶段首先完成真实 Windows 键鼠、中文输入法、文件对话框、高 DPI 和显卡异常验收，再扩大格式或平台范围。现有检查点可以试用，但不能把同机测试通过当作生产成熟。

## 第一阶段：Windows 兼容和可恢复性

在 Windows 10 与 Windows 11 的干净环境上解压同一未签名包，保留系统安全策略，检查启动、D3D12 adapter、系统字体回退、中文路径和读取权限。以真实输入执行连续翻图、文本框焦点、拖拽裁剪、滚轮缩放、Esc、全屏和最小窗口导出。测试真实系统 DPI 切换以及多显示器移动，核对像素/逻辑坐标与选区一致。输入法测试包括中文组合输入、候选框及组合期间方向键不被浏览快捷键截获。

GPU 初始化失败须有可读诊断；设备丢失须停止新的 GPU 工作、取消在途编辑/导出并允许重新打开原素材。不能依赖失效 GPU 绘制唯一的错误提示。先通过受控的本应用设备失效验证错误路径，再由真实驱动事件验证，分别记录结果。源文件仍绝不覆盖；未提交的临时副本可清理，不自动恢复或悄悄发布中断导出。

资源验收覆盖连续查看数百张高分辨率透明/ICC 图片、不同边长和导出后恢复，检查逻辑预算归零与进程私有内存的长期趋势。分别记录空闲、热路径、冷启动可见帧和截图回读；按显卡/驱动列出 MemoryUsage 的效果，不将本机结果推广到所有 GPU。

## 第二阶段：共享代码的 Metal 验证

保留 Rust 图像处理、来源 worker 协议、编辑/导出接口以及 egui UI。平台层只负责文件选择、系统字体、资源约束、窗口启动与图形后端。Mac 第一项工作是 arm64 + Metal 的同一界面和 JPEG/PNG 查看/导出小范围验证，而非完整 Mac 产品。必须有真实 Mac 构建和运行记录；当前 Windows 环境的配置路径不是 Mac 验收证据。

Mac worker 的进程内存/生命周期限制需单独设计，不能把 Windows JobObject 等同为跨平台沙箱。离线策略保持相同：HTTP/远端 manifest/OCSP 显式关闭，不自动上传图片或查来源。实际 Mac 系统字体只在运行时加载，分发许可字体需包含完整通知。测试 Retina 坐标、Command 快捷键、Unicode路径、文件对话框和透明导出后，再讨论签名及发行；签名证书或发布必须取得新的授权。

## 第三阶段：收益明确的功能增量

优先考察 BMP/静态 WebP 对真实素材目录的覆盖收益。每个格式先写独立解码/色彩/alpha/导出和攻击面设计，确认已锁定解码器以及上限，再开启依赖 feature。动图不静默取首帧。批量处理必须先设计可取消队列、逐文件命名冲突、预算共享、失败隔离与原图保护，不在当前单文件闭环旁复制第二套实现。

水印单独实验并明确可被移除的边界；它不替代 C2PA 或真实性判断，也不优先于浏览、正确色彩和安全导出。用户价值与实际测试决定后续顺序，语言熟悉度或实现难度不作为换成双原生 UI、Electron 或 Qt 的理由。

## 交付标准

每一阶段交付独立实施设计、可复现的锁定源码、配对可执行包及许可通知、实际平台测试结果、已知限制和未完成项。没有签名证书时保持“未签名测试版”标记；不改变系统安全设置，不建立持久凭据。仍需阅读原始 v0.2 文档的图表，核对实现与基线，保留输入文档身份。
