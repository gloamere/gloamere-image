# 检查点审查后的加固设计（实现前，2026-10-07）

审查针对 e565677 后工作树提出三个静态疑点。当前代码确认导出窗口未绑定世代、导出线程没有 panic 转换、接收端忽略断开；总内存仅限制解码器，无法作为操作峰值上限。先修复这些问题，不增加格式和批处理。

## 真实场景与行为

用户为 A 选择导出名称后拖入 B：立即关闭 A 的导出窗口，加载期间不能导出。导出意图必须绑定图片世代，开始导出时再次检查世代、加载状态和 ICC 校准状态。ICC 不可处理的 B 仍可浏览，但不能导出带 sRGB 声明的副本。异步编辑结果到达时关闭旧导出意图，重新确认名称。

后台线程异常或发送端断开：清除忙碌状态并显示可恢复的错误；后续打开、编辑、导出可以继续。取消与异常不混淆。来源任务也处理断开。

## 内存与主线程工作

将首版支持上限收紧到 1600 万像素、64 MiB 文件、128 MiB 解码器分配；这不是已经达到的性能预算。核心新增操作峰值估算接口，操作前按输入/输出像素、解码中间值、浮点重采样中间值和输入快照做保守预留，超过 768 MiB 估算预算拒绝操作。UI 计算不可重复计数的原图/编辑图/撤销图及 egui CPU 纹理、GPU 副本；加载新图、编辑和导出前先淘汰可释放撤销历史。加载保留上一张时纳入估算；取消的后台工作未退出前不启动第二个编辑/导出。

限制是应用估算与准入，不等于全进程硬内存沙箱；字体、驱动和 SDK 内部实际峰值必须由 Windows 进程采样补充。C2PA 子进程仍有独立 512 MiB JobObject 上限，不把它当作主进程预算。若实测不符，继续收紧上限。

ICC 转换不再复制全图输入，按行读取已解码像素、写入独立目标，失败保留完整未转换图，不显示半转换图。像素转换完成即释放解码缓冲。目录枚举移至加载线程，避免 UI 做文件系统扫描。

JPEG 底色变化不重建全尺寸画布纹理。导出窗口展示最长边 512 的预览：后台按相同 flatten 函数生成，CPU/GPU 均有固定上限；结果绑定世代和底色，旧任务取消后其结果丢弃。原画布保持透明棋盘格。缩略图不是导出精确像素或 JPEG 压缩效果证明。

## 验收与证据边界

新增回归：A 开导出→B ICC 失败、A→异步替换、后台 panic/断开后恢复；内存估算的临界值、透明长宽极端缩放的中间缓冲、超限输入拒绝；大图/ICC/导出真实 Windows 峰值采样、空闲重绘采样。实际 worker 集成测试在构建后显式启用，并使用官方签名、篡改、remote manifest、OCSP 夹具。配置/拒绝 resolver 的测试只证明对应路径，不替代系统网络捕获。当前未具备真实鼠标/IME 自动化工具，合成 egui 输入与实际用户输入分别报告。
