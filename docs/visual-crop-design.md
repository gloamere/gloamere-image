# 可视化裁剪设计

用户场景：开发者/内容制作者希望凭画面去掉截图边缘或选择主体，而不是先估算 X/Y/宽高。首版数值裁剪已可用；增加画布选择作为同一个 EditOp::Crop 的输入方式，不引入第二套图像处理或自定义 GPU 渲染。

在编辑区用明确“拖拽选择裁剪”模式切换。默认画布仍为浏览平移；裁剪模式下主键从图像内开始拖出选区，次键仍可平移。滚轮缩放保留像素坐标选区。拖拽端点经当前画布图像矩形逆变换到当前已旋转/编辑图片的像素空间，约束到边界，支持反向拖拽，起点 floor、终点 ceil，非空至少 1 像素。数值控件与视觉选区保持同步。坐标标签改为“当前图片像素坐标”。

选区只用 egui painter 矩形边框、三分网格与边外遮罩呈现；不复制像素、不创建额外纹理。移动/裁剪选择期间不写文件。“应用裁剪”使用现有有界异步编辑管线，保留原图、撤销、取消、来源证据失效和陈旧导出保护。切图、成功编辑、恢复原图时清理陈旧拖拽状态并重置尺寸。Esc 优先关闭最上层对话框，然后取消裁剪选择模式，再退出编辑/全屏。

非目标：本轮不增加选区手柄调整、自动主体识别、AI 修图、批处理、Mac 完整产品或水印；这些不能占用安全导出与冻结时间。最迟截止前 60 分钟停止新增功能，保留质量检查、portable 重建和交付整理时间。

验收：纯坐标转换的反向/边界/缩放/高 DPI 等价测试；通过实际 App::ui 的内部指针事件验证选择不触发平移，模式退出和切图清理；裁剪后 PNG/JPEG 新副本及原图 hash 不变回归。实际 Windows 自身渲染查看选区、编辑/来源说明和最小窗口。当前环境没有可用前台自动化入口，真实拖拽手感与键鼠/IME仍未验收，不能用内部事件测试代替。
