# Independent model-target protocol addendum — 2026-10-10

This addendum precedes the model-update extension. A model auto-update choice must have a real controlled implementation, and never inherit the application auto-update choice. Consent remains in the caller: initial component download requires its own explicit action; automatic checks/downloads apply only to an already-installed component when that component's update choice is enabled. Updating a model never enables automatic image screening or uploads.

Use the same authenticated TUF repository and bounded transport, but a separate opaque `VerifiedModelTarget`, release sequence floor and quarantine scope (`product/platform/channel/model/model_id`). Application release floors and quarantine are unaffected. The repository channel is distribution policy, not model quality. No remote `approved`, `stable`, quality-tier, command or runtime-install field is accepted.

The caller builds `ModelCompatibility` from the application's compiled model allowlist. Exact fields include model ID; content-addressed model version (the existing weights SHA-256); manifest schema; preprocessing; worker protocol; runtime version; upstream source revision; full `pack_fingerprint`; and a compiled license-set identifier plus the exact license-file list. The exact manifest SHA-256 and expanded byte count are also compiled pins, independently checked after extraction. Current profile is schema2, worker1, ONNX Runtime1.28.3 and the existing experimental CoDE preprocessing/fingerprint. The fingerprint already binds weights, native runtime, JPEG decoder and research policy. A publisher signature cannot authorize a novel graph, DLL or quality status; such changes require a separately reviewed application allowlist update.

Signed target name: `models/{model_id}/{model_version}/{platform}/{release_id}/model-pack.zip`. Consistent-snapshot download prefixes the zip basename with its SHA-256. Signed custom fields bind the exact compiled profile, a monotonically increasing model `release_id`, app-protocol minimum, unpacked length and rollout. The ZIP is capped at 256 MiB and its declared unpacked size at 512 MiB. The activation layer must independently enforce actual ZIP paths/count/expanded-size budgets, exact file manifest/hash whitelist and synthetic self-test before atomically switching the active pack. This core downloads bytes only and never extracts or executes them.

Revalidate the opaque target, metadata floor snapshot, clock, expiry, exact current compiled profile, release floor and quarantine immediately before activation. Failed activation keeps the old verified pack and may quarantine only that model release; no trust floor is lowered. Test with authentic ephemeral signed metadata and in-memory transport, including app/model independent sequences, wrong identity/schema/preprocessing/runtime/worker/license, forbidden approval fields, replay, quarantine, stale selection and bounded sizes. Production remains unavailable without embedded trust and normally validated IP HTTPS.

Pause is a resumable interruption: a cancellation token stops the current request while a valid strong-ETag-bound partial/state is retained. If the origin supplies no valid strong ETag, no resumability is claimed. Explicit destructive cancel remains the caller's exact-task cleanup after the download lock is released. Integrity, Range, origin and content-policy failures never retain a partial as trusted future resume input.

## Controlled integration fixture support

The default-off `fixture-harness` feature exposes one bounded metadata-bundle verifier for integration tests. It accepts metadata filename/byte pairs, runs the unchanged TUF/profile/monotonic-state verification path and returns a `TrustedRepository`. Tests then call normal model selection and activation revalidation to obtain/use genuine opaque authority. It does not supply an unchecked target constructor. It has no production fallback or network transport override; a compile-time guard rejects normal release builds with this feature. Enable it only in the integration harness/dev dependency, never in production dependencies. Actual ZIP extraction, current graph/DLL allowlist and synthetic self-test remain application-layer checks.
